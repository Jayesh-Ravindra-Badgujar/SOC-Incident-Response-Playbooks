
# NIST Incident Response Framework

## Overview

The **NIST SP 800-61 Rev. 2 (Computer Security Incident Handling Guide)** is a widely adopted framework that provides best practices for preparing, detecting, analyzing, containing, eradicating, and recovering from cybersecurity incidents. It serves as a standard reference for Security Operations Centers (SOCs), Incident Response (IR) teams, and cybersecurity professionals.

---

## Purpose

The NIST Incident Response Framework helps organizations to:

- Establish a structured incident response process
- Reduce the impact of security incidents
- Improve investigation and response efficiency
- Standardize incident documentation
- Strengthen organizational security posture
- Support continuous improvement through lessons learned

---

## Incident Response Lifecycle

The framework defines six phases of incident handling:

### 1. Preparation

Prepare personnel, tools, policies, procedures, and communication plans before an incident occurs.

### 2. Detection and Analysis

Identify, validate, and analyze security events to determine whether an incident has occurred.

### 3. Containment

Limit the impact of the incident by isolating affected systems and preventing further compromise.

### 4. Eradication

Remove the root cause of the incident, including malware, unauthorized accounts, or persistence mechanisms.

### 5. Recovery

Restore affected systems to normal operation, verify system integrity, and continue monitoring for any signs of recurring activity.

### 6. Post-Incident Activity (Lessons Learned)

Review the incident response process, identify areas for improvement, and update policies, procedures, and detection rules.
